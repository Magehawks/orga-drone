# Color Workspace contract (proposed, Phase A / #348)

This is the normative companion to [ADR 0035](../decisions/0035-color-workspace-contract.md). All new structures, interfaces and limits below are proposed and unimplemented. Baseline: develop `8ff25454672de14b312e5b9e4d553a9c57d1b8ef`.

## Verified current implementation and gaps

- `studio_image.py`: `ImageAdjust` persists `image` with integer exposure, contrast, saturation, warmth, highlights, shadows, blacks (-100..100). `ffmpeg_grade_chain` orders warmth, exposure, YUV eq contrast/saturation, then colorlevels. Exposure is +/-1 stop at full travel, measured encoded multiplication; warmth is a +/-60 mired shift around 6500 K. Tonal controls alter input bounds; they do not recover clipped data. Legacy formulas and clamping remain unchanged.
- `studio_lut.py`: `color` contains profile, confirmed conversion LUT, creative LUT and strength. Local asset names are confined; missing LUT blocks export. Cubes support 2..65 edges, red-fastest data and tetrahedral FFmpeg interpolation. The current parser skips matching DOMAIN lines rather than carrying a domain model. Do not infer managed-domain support from successful import. Creative strength below 100 generates a blended cube.
- `studio_hsl.py`: `hsl.ranges` has eight ranges, smooth hue weights/gray gate, +/-45 degree hue, 0..2 saturation and +/-0.30 HSL lightness, baked to 33-cube.
- `studio_color_wheels.py`: `color_wheels.wheels` stores unit-disc points for shadows/midtones/highlights, zero-luma tint and smooth tonal weights, also a 33-cube. These are not lift/gamma/gain controls.
- `studio_color_animation.py`: version-1 `color_animation`, at most eight linear keys, replaces four image sliders and optionally creative strength within a clip-relative bar. `saturation_ramp` is a separate legacy structure. `expand_export_clip_for_color` has eligibility restrictions; general animated spatial grading is not available.
- `db/__init__.py`: existing per-feature setters store `effect_settings`. `studio_history.py` snapshots full clip rows in process memory. History is session-only; reopen must preserve saved grade, not the undo stack. Existing dump functions preserve unrelated top-level keys, but can replace nested feature objects; they are not sufficient for canonical unknown-field preservation.
- `app.py` and `templates/studio.html`: `/image`, `/color`, `/hsl`, `/color-wheels`, `/color-animation` routes and data-image-adjust/data-color-look/data-hsl/data-color-wheels/data-color-animation fields form an existing server/DOM contract. The DOM-backed clip model has no independent grade shadow store. These interfaces cannot be repurposed in parallel.
- `studio_actions.py`: shared actions include clip.color.image/look/hsl/wheels, strict payload validation, legacy static-color restrictions, and supported-target capabilities. Control API/MCP are consumers of the same actions, not alternate grading engines. #296 is the separately scoped image-target follow-up; #280 is closed. Capability restrictions must be verified per action, not inferred from a visible slider.
- `export/studio_encoder.py::_segment_chain`: grade, conversion/creative LUT, HSL, wheels, detail, saturation ramp, framing/scale. Privacy masks, overlays, fades and compositing have their own later orchestration. `studio_preview_frame.py::preview_filter_chain` shares color builders but has a JPEG boundary and does not establish full export-detail equivalence. Its cache version is 7. `studio_playback_proxy.py::proxy_filter_chain` scales BEFORE grading for cost, then emits BT.709 limited yuv420p; cache identity includes LUT content. Proxy version is 3.
- `static/js/studio-lut-webgl.js`: WebGL2 path applies approximate RGB warmth/exposure/contrast/saturation, conversion and creative LUT, then saturation ramp. Managed bake LUTs sample tetrahedrally via `texelFetch`. LUT table storage is capability-gated (RGBA32F/16F when upload works → operator-exact; else RGBA8 with `exact:false`). HSL/wheels and other unsupported stages are gated elsewhere; never claim this shader covers spatial grades.
- Existing regressions include `tests/test_studio_image.py`, `test_studio_lut.py`, `test_studio_hsl.py`, `test_studio_color_wheels.py`, `test_studio_color_animation.py`, `test_studio_history.py`, `test_studio_preview_frame.py`, `test_studio_playback_proxy.py`, `test_studio_lut_pixel_parity.py`, `test_studio_color_probe.py`, and Node LUT/preview/proxy/color-compare harnesses. Reuse them; new independent evidence files do not authorize concurrent edits to them.

Absent as a unified workspace: versioned canonical grade, full curve family, spatial color qualifiers, linear/radial/brush grading masks, professional primary parameter contract, all four scopes, and serial operation editing. Privacy blur masks are not color masks. The package backlog covers every gap without claiming it is shipped.

## Data envelope and authority

Proposed JSON shape (illustrative neutral managed grade; not accepted by today's API):

```json
{
  "grade": {
    "schema_version": 1,
    "evaluator": "managed-sdr-v1",
    "revision": 1,
    "input": {"profile": "srgb", "technical_lut": null},
    "working": "linear-bt709",
    "steps": [],
    "selections": [],
    "animation": [],
    "output": {"profile": "bt709-sdr", "gamut": "clip"},
    "extensions": {}
  }
}
```

`revision` is a monotonic server-assigned edit token, not render semantics. It increases on accepted edits and undo/redo so stale completions cannot regain authority. `schema_version` is a positive integer; evaluator IDs are immutable. Finite JSON numbers only, no NaN/Infinity, duplicate IDs or dangling references. Structural limits proposed: 32 steps, 32 selections, 4096 points per curve and 100000 brush points per clip; a 4 MiB grade JSON request ceiling. Reject an oversized edit atomically. These are safety limits, not a reduction of supported tool types; changes require measured justification and contract version review.

A step has `id` (stable opaque identifier), `type` (versioned operation ID), `enabled` (boolean), `mix` (0..1), `params` (typed object), and `selection_id` (null or a valid selection). Input/output domains come from the registered type contract, never arbitrary shader/filter strings supplied by clients. Steps execute once in array order. Disabled steps bypass evaluation but remain stored. Empty steps means identity grading, not identity input/output transfer conversion. Missing grade means legacy; `grade:null`, malformed grade, null scalar or unknown evaluator are errors, not implicit reset. Missing optional step parameters materialize documented neutral defaults; a reset is an explicit command. Empty selection resources alone have no effect.

Preserve unknown object members recursively on roundtrip, including disabled unknown operations, but reject edits to unknown fields. Unknown enabled operations block render with UNSUPPORTED_GRADE; disabled unknown operations may be preserved and bypassed. Unsupported versions are read-only and cannot be overwritten through legacy setters. A complete reset must require explicit intent to discard unsupported content. Renderer/cache canonicalization uses known active semantics plus evaluator version; opaque active semantics cannot produce an apparently valid render.

### Compatibility and migration sequence

1. Add a pure read adapter, with fixtures for missing/invalid legacy keys and every current grade/animation combination. No write on read, scan, thumbnail or export. Legacy fallback behavior remains exactly as today's readers, including their invalid-value defaults.
2. Introduce guard/read capability negotiation in every existing write path: UI routes, shared actions, Control API/MCP, presets, cut/merge/reuse, reset and history restoration. Unknown canonical grades must never be rewritten by a legacy setter. First canonical write is gated on all these paths being safe.
3. Explicit wrapping creates `evaluator:legacy-v1` with a single `legacy-stack-v1` operation carrying original color keys (`image`, `color`, `hsl`, `color_wheels`, `detail`, `saturation_ramp`, `color_animation`) including unknown members. Retain the entire pre-conversion effect_settings in a local recovery record with checksum. Other effects remain outside the envelope and unchanged. Frozen old color keys are provenance only; the envelope alone is read after wrapping. Native legacy rendering uses the old builders; do not roundtrip through a resampled cube.
4. Use one transaction/one history gesture to publish a canonical edit and revision. Validate first; no partial clip, asset or history mutation on failure. Undo restores complete grade and opaque data; redo restores the next state. Revision is regenerated rather than restored. Save/reopen preserves grade/IDs; process restart still drops the session undo stack. Rescan must retain grade as it retains studio_clips today.
5. Managed conversion is a separate explicit command. Keep legacy recovery data, identify untranslatable operations, and require acknowledgement of changed appearance. No automatic conversion on slider focus or Creative/Pro mode switch. If conversion cannot represent animation/masks safely, reject and leave the legacy clip editable in its existing profile.
6. Minimum compatible application/grade-reader version must be checked before first write; old executables lack that check. Therefore use a backed-up, separately versioned local database for the canonical-capable application and never direct an old executable at it. The migration issue must specify actual backup naming, verification, restore and desktop startup gating before implementation approval. Downgrade uses the verified pre-upgrade database; it loses later edits and must state that. Recovery data is not a lossless old-binary downgrade for new tools.

No migration runs in Phase A. A proposed envelope alone does not make mixed-version writes safe.

## Managed SDR numerical contract

### Input, output and domains

Normalize EXIF orientation once; decode video using declared matrix/range/transfer/primaries. Tagged sRGB photos use inverse sRGB transfer; tagged BT.709 SDR video uses inverse BT.709 transfer. Untagged photos propose sRGB and untagged SDR video BT.709 limited as explicit, visible assumptions recorded in the plan; HDR/PQ/HLG, unknown camera logs or incompatible tags require a selected supported input transform, otherwise UNSUPPORTED_INPUT_PROFILE. Do not auto-apply guessed log transforms.

BT.709 linear primaries use D65; luma Y = .2126 R + .7152 G + .0722 B. sRGB decode is c/12.92 for c<=.04045, otherwise ((c+.055)/1.055)^2.4. BT.709 decode is c/4.5 for c<.081, otherwise ((c+.099)/1.099)^(1/.45). Inverses use the corresponding branch thresholds. Negative values use the linear toe branch. Input matrix/range conversion precedes transfer decoding. HDR is not implicitly compressed into SDR.

A confirmed technical LUT can replace the input transfer/primaries adapter: its asset metadata must declare input and output profile. If it emits encoded BT.709, decode that once; if linear BT.709, do not decode again. Reject conflicting simultaneous conversion choices. D-Log M hints do not establish colorimetric calibration. Local user LUTs are user-declared transforms, not certified camera profiles.

Managed export encodes BT.709 transfer and limited-range BT.709 yuv420p using the existing MP4 encoder. Browser canvas presentation encodes sRGB; metadata is part of the boundary. These presentation code values MUST NOT be compared directly with BT.709-encoded export RGB. The separate managed comparison below normalizes both to a declared common boundary; it does not modify the legacy #320 extractor or gate. Quantization, chroma subsampling and scaler implementation are recorded, not assumed to commute. Alpha remains straight internally; operations affect RGB, preserve alpha, and use zero RGB when unpremultiplying zero alpha. Linear-light RGB blending is used within managed steps. Final project transitions retain current legacy compositing until the dedicated gate approves a different contract. Scopes of graded pixels are distinguished from scopes of the project composite.

No clamp between linear operations except explicitly bounded operations. Before output transfer, hard clip linear channels to [0,1] for this profile; gamut policy is recorded. This is not highlight recovery or a perceptual gamut compressor. Bounded encoded HSL/LUT inputs clamp only at the explicit domain adapter. Nonfinite intermediate values fail the render. CPU reference arithmetic is float64; adapter intermediates must be at least float32 until documented quantization boundaries. This is a target for the new profile, not permission to change legacy filter precision or restore the rejected #320 patch.

### Primaries and wheels

Managed operations have versioned IDs and units, separate from legacy sliders. `primaries-v1` runs exposure, balance, contrast, tone, saturation in that order:

- Exposure E in stops [-10,10]: RGB *= 2^E.
- Balance uses positive RGB gains [.01,100], normalized so their luma-weighted sum is 1, applied diagonally in linear RGB. Identity is [1,1,1]. Kelvin/tint UI conversion must publish one versioned mapping and golden vectors before wiring; it may not invent an independent frontend approximation. Legacy warmth remains its existing blackbody function.
- Contrast k in [0,4], pivot p in [.001,1]: p * sign(RGB/p) * abs(RGB/p)^k; k=1 is identity, k=0 is defined as p for positive inputs, -p for negative, zero for zero. Do not call this legacy YUV contrast.
- Tone is a monotone piecewise-linear scalar Y map with endpoint extension; defaults [(0,0),(1,1)]. Reconstruct RGB by adding f(Y)-Y to every channel. Blacks/shadows/highlights/whites controls generate this same curve through a versioned mapping locked by vectors; no second hidden tone operator. The feature issue must publish that mapping and gain approval before coding the controls.
- Saturation s in [0,4]: Y + s*(RGB-Y); s=1 identity.

`wheels-v1` offers explicit lift/gamma/gain/offset parameters: gain >=0, gamma >0, unrestricted finite lift/offset within declared UI bounds. Per-channel result is sign(z)*abs(z)^(1/gamma)+offset with z=(x+lift)*gain. Neutral lift/offset=0, gamma/gain=1. Existing three tonal tint wheels remain `legacy-wheels-v1`; new tonal tint controls can reuse their documented math in an explicit encoded-domain adapter. Do not silently map a two-dimensional old wheel into lift/gamma/gain. Pro mode must expose which operation is being edited.

### Curves, HSL and serial operations

`rgb-curves-v1` uses piecewise-linear interpolation, strictly increasing x, finite y and endpoint-segment extrapolation. Evaluate master R/G/B-independent curve first on each channel, then each channel curve. Identity is [(0,0),(1,1)]. Domain is explicitly linear or bounded BT.709 encoded, chosen in params, never inferred from UI mode. `luma-curve-v1` maps Y and adds f(Y)-Y to RGB; this defines behavior at black without division.

Complete additional curve set: Hue-vs-Hue, Hue-vs-Saturation, Hue-vs-Luma, Luma-vs-Saturation and Saturation-vs-Saturation. Evaluate HSL in bounded BT.709 encoded RGB using the existing RGB/HSL definitions. Hue curves are periodic at 360 degrees with matching endpoints and shortest signed hue offsets; saturation/luma x axes are [0,1]. Hue-vs-Hue adds degrees, Hue-vs-Saturation multiplies S, Hue-vs-Luma adds L, Luma-vs-Saturation multiplies S using encoded BT.709 luma, Saturation-vs-Saturation maps S directly. Clamp S/L after each encoded operation; gray pixels below chroma 1e-6 bypass hue-based operations. Neutral hue/luma offset is 0, saturation multiplier 1, saturation mapping identity. Each curve is an independent serial type; order is visible. Piecewise linear is the first interpolation contract; smooth/Bézier editing must compile to the same explicit points within measured error or get a versioned evaluator.

Reuse `hsl` and existing wheel reference functions for legacy adapters. New managed HSL is a distinct encoded-domain step so legacy clamping/quantization is not accidentally redefined. Operation-type metadata includes whether it is pointwise/LUT-bakeable or spatial. Only contiguous pointwise stages with matching domains can be fused; fusion requires measured error versus unfused evaluation. Masks, qualifiers with a matte image, geometry, detail and scopes cannot disappear into a global color cube.

### LUT assets and sampling

Preserve confined local asset access. A canonical LUT reference includes asset ID, SHA-256, size, DOMAIN_MIN/MAX, input/output profile, interpolation ID and precision. Parse and validate 3D cubes, red-fastest indexing, exactly N^3 finite triples, 2<=N<=65; reject duplicate headers, non-increasing domain bounds, malformed domains, unsupported 1D/shaper variants and ambiguous profiles with actionable errors. Support for 1D/shaper LUTs is separately versioned follow-up if required, never silently ignored.

Sample coordinate u = clamp((c-domain_min)/(domain_max-domain_min),0,1)*(N-1). Use tetrahedral interpolation with descending fractional coordinates; ties resolve R before G before B. For order a,b,c and fractions fa>=fb>=fc, interpolate V000 + fa*(Va-V000) + fb*(Vab-Va) + fc*(V111-Vab). Creative strength m: (1-m)*input + m*sample, in the LUT's declared input/output-compatible domain; reject a creative LUT whose output cannot be explicitly transformed back into that blending domain. Technical LUT has no strength and executes exactly once before grading. Zero-strength creative LUT bypasses both sample and its domain clamp. Do not round table values to 8-bit before sampling. GPU tetrahedral implementation extends the existing WebGL adapter only after the LUT precision/detail gate passes. Trilinear or baked/fused approximations require explicit capability labels and cannot certify exact parity.

## Spatial selections and time

Selection objects contain stable ID, mask expression, qualifier and invert flag. No selection means full coverage; empty enabled selection has zero coverage. Mask expression is an ordered list of linear, radial or brush leaves combined with union=max, intersection=min or subtraction=max(0,a-b). All mattes are [0,1]. Linear coverage is smoothstep(-f/2,f/2,d) on signed distance to a normalized line; radial is 1-smoothstep(1-f,1+f,r) on elliptical radius. At f=0 use a hard threshold. Brush stores normalized source-coordinate polylines, pressure/radius and hardness; rasterization samples pixel centers, evaluates distance to segments and smoothstep falloff from hardness*radius to radius, combines strokes by max or subtract. Brush rasterizer version and sampling resolution enter the plan/cache; soft coverage must not depend on canvas device-pixel ratio.

Coordinates are normalized [0,1] in the oriented source picture, before framing; feather/radius use fractions of the source's shorter dimension with explicit conversion for elliptical axes. Clip trim/repeat/speed do not reinterpret geometry. No geographic coordinates or automatic object semantics. Tracking later supplies versioned time-dependent geometry through this same interface, with lost-track status and manual fallback; no tracking is claimed now.

Qualifier reads the unmodified RGB input of its own step in bounded encoded BT.709; RGB selectors use channel intervals, HSL selectors use wrapped hue and saturation/lightness intervals, luma selector uses encoded BT.709 luma. Each interval has inner fully-selected and outer zero-selected bounds joined by smoothstep; hue wraps, gray below 1e-6 fails a non-full hue selection. Combined channels multiply. Selection coverage = mask coverage * qualifier coverage, then optional invert (1-coverage). An eyedropper returns the sampled value plus domain/frame/revision and neighborhood bounds; UI explicitly accepts it to change selector ranges. It does not identify water, sky or objects.

For step input C, processed P, mix m and coverage q: output C + m*q*(P-C), alpha unchanged. Qualifier is not re-evaluated on P. Matte generation is independent of output resolution; reference evaluation happens at oriented source resolution. Resampling mattes is a reported approximation.

RenderContext carries rational source PTS/frame index, clip source in/out, clip-local source seconds, Story seconds, speed/repeat-pass mapping and transition side. Legacy animation uses the existing source-relative behavior and eligibility; preserve it through the wrapper. New animation stores an explicit clock (source-local or Story-local) and target step/parameter ID, with linear interpolation and outside-range hold/base policy explicitly encoded. Unsupported animated types reject, not flatten. Mapping is supplied by existing timing owners; a grading feature cannot change playback clocks. Boundary vectors must include trims, speed ramps, repeated clips and both sides of a transition.

## Engine, workspace and evidence interfaces

These are proposed logical interfaces; no endpoints or modules exist merely because named here.

- Engine `read_grade(effect_settings)` returns authority/profile, opaque-preserving model, supported operations, revision and diagnostics. `validate_patch(current, command, expected_revision)` returns a new model or typed atomic error. `evaluate_grade(model, RenderContext)` returns RenderPlan and semantic digest. No DOM, filesystem mutation or UI string generation in these pure functions.
- `RenderPlan` carries schema/evaluator/adapter versions, ordered typed operations with domains, resolved asset digests, evaluated animation, selection/rasterizer identity, geometry, output profile, source identity and capability requirements. Asset resolution and confined filesystem reads happen outside pure math. No arbitrary FFmpeg expressions accepted from UI/MCP.
- Adapter `render(plan, source, target)` returns image/video resource plus actual format/color tags, exact/approximate status, omitted/unsupported stage diagnostics, timing and resource measurements. Still, playback and export consume the same plan. Unsupported export fails before publication; preview fallback must be explicit and must not double-apply CSS/grade on an already graded proxy.
- Workspace snapshot contains project/clip IDs, revision, operation descriptors (units/ranges/defaults/enum/support), input/output profiles, resource IDs and capabilities. Commands are add/update/remove/reorder step, set selection, set input/output, apply preset, explicit reset and convert profile. Each command supplies expected revision and project/clip target. Undo groups a gesture into one transaction; mode switches change presentation only. Use existing shared action architecture and Host/Origin checks.
- Server response supplies new revision/digest and refreshed snapshot. Stale edits return conflict without mutation; unsupported input/grade/LUT returns precise typed errors. A preview token includes project, clip, revision, request generation and context digest. Late responses never replace a newer view. Transient drag previews are labeled unsaved and do not rewrite the persisted snapshot until committed.
- Evidence input consists of fixture manifest, source hashes, grade JSON, plan JSON, build/FFmpeg/WebView2/GPU identity, adapter settings and exact frame mapping. Output records raw captures, decoded export frames, masks/ROIs, metric implementation/version, per-case PASS/FAIL/NOT_RUN, source-after hashes, performance samples and stderr. A process success or `ui_applied` does not prove pixel correctness. OpenCode compares plans and pixels independently rather than importing the engine's expected result as its oracle.

## Scope tap and quantitative display contract

Proposed `ScopeFrameV1` contains an immutable RGB buffer handle, dimensions/stride, profile/transfer, straight-alpha flag, rational PTS/frame index, project/clip/revision/context digest, tap ID, ROI and sampling factor. Default tap is the current clip after its grade and before framing/output encoding, converted through the declared output profile to bounded BT.709 encoded RGB. A project-composite tap must be explicitly requested and separately labeled; it does not silently replace the clip tap. Matte view is a separate grayscale diagnostic. Scopes cannot mutate or feed back into the render plan.

Reference sampling uses every pixel center in the requested ROI, ignores alpha=0 and weights other samples by alpha. Histogram channel bin is min(255,floor(256*c)); luma uses Y'=.2126R'+.7152G'+.0722B'. Histogram reports absolute weighted counts and normalized counts separately. Waveform horizontal coordinate is normalized source x and vertical coordinate is Y' (0 black, 1 white); RGB parade uses the same coordinates and separate R'/G'/B' panels. Density is accumulated sample weight, never a different transfer function. Legal-range video code values are expanded to normalized [0,1] before these calculations; mark legal-range boundaries separately rather than double-expanding.

Vectorscope uses BT.709 encoded opponent coordinates Cb=(B'-Y')/1.8556 and Cr=(R'-Y')/1.5748, centered at (0,0), with axes [-.5,.5]; Cb increases right and Cr increases up. Color-bar target coordinates are computed from these same equations. No arbitrary rotation or skin-line calibration claim is introduced. Waveform/parade/vectorscope density display uses log1p(count) normalized to the largest count only for visualization; raw counts remain available to the harness. UI resolution reduction bins already evaluated samples; optional pixel subsampling must report its factor and deterministic sample grid and cannot certify the full-resolution reference gate. Engine tap and numerical accumulation are Codex-owned in their own gate; Cursor owns display only, OpenCode verifies independent counts.

## Cache, fallback and performance

Semantic digest includes evaluator, ordered active params, input/output transforms, LUT bytes/domain/interpolation, mask content/rasterizer, evaluated clock, source identity (path under root + size/mtime; content hashes in evidence), geometry, dimensions, scaler, precision, adapter/version and encode format. Revision guards display freshness but is excluded from semantic reuse. Still quantization and proxy interval/FPS must be explicit; export frame-index tests cannot reuse an approximate seek still as ground truth. Never key only on LUT filename. Content replacement, reset, undo, profile/selection changes and implementation changes invalidate affected artifacts. Exclude unrelated UI mode/title changes. Write cache files atomically and evict only owned rebuildable caches; cancellation never publishes a partial export.

Proposed admission budgets, to confirm on recorded Windows baseline hardware: 1080p30 GPU simple-grade p95 render <=33.3 ms; input-to-correct-preview p95 <=150 ms for warm-cache pointwise edits; zero added still fetches during fixed playback intervals. For 4K/spatial plans, report actual p50/p95, peak RSS/VRAM, first-result latency and dropped frames; unsupported real-time plans fall back to an explicitly preparing proxy, not skipped grading. Compare same-source baseline/candidate with cold/warm runs (at least 5 measured runs after warmup); >10% wall-time or memory regression needs explicit PO acceptance before retention. These are proposed gates, not measurements. Performance rejection must split/optimize implementation, not remove a product feature. Existing #320 detail-retention conditions remain stricter where applicable.

## Evidence and review gates

Legacy gate L320 applies to legacy-v1 only: reuse #320's exact existing metric implementation and ROIs, maximum swatch RGB error <=3.0. Do not substitute per-image mean, change decoder, omit failing samples, or raise tolerance. Strict reference is actual application-exported MP4 at matched frame index/PTS; raw float reference is an additional operator test, not a replacement. Separate decoder, LUT interpolation, transfer, precision, scaling, chroma, JPEG and compositor residuals. Lossless CPU/GPU operator gate proposed: maximum absolute channel error <=1e-5 for float paths before output encoding; bounded approximations must publish separate measured errors and cannot claim exact status.

### Separate managed gate M709-SRGB8-v1

This is a proposed NEW gate for `managed-sdr-v1`, not a correction to L320 or a replacement for any historical result. Both gates retain separate IDs, manifests and verdicts. Running a legacy clip through managed normalization is not a valid L320 result. A managed PASS cannot close #320; a legacy FAIL stays FAIL. New managed presentation transfers are deliberately different code encodings of the same relative linear color, not a promise of identical values on arbitrary video displays (BT.1886/display calibration is outside this arithmetic gate).

Common comparison colorimetry: BT.709/sRGB primaries R=(.640,.330), G=(.300,.600), B=(.150,.060), D65=(.3127,.3290); relative linear RGB white=(1,1,1), black=(0,0,0). Convert both buffers to straight-alpha linear RGB in those primaries, then encode **both** using the same sRGB function and quantize once to full-range RGB8. No chromatic adaptation or primaries matrix is needed between these two profiles. Different/unknown primaries, missing/contradictory metadata, HDR or unrecorded browser color conversion invalidate the managed test instead of being guessed. The declared input assumptions elsewhere concern source interpretation; they do not authorize ambiguous output capture.

Boundary procedure, versioned as a whole:

1. Pin build SHA, FFmpeg binary SHA/version/build flags, software H.264 decoder, libswscale version, WebView2/GPU/OS color settings, pixel format, output dimensions and exact rational frame PTS/index. Disable hardware video decode in the reference; no seek-time-nearest selection. MP4 must declare BT.709 matrix/primaries/transfer and limited range. Decode the actual application-exported MP4, never a surrogate filter invocation.
2. For MP4, obtain encoded full-range R'G'B' as planar float32 using the pinned software decoder and libswscale YUV-to-RGB conversion: BT.709 matrix explicitly selected, limited input to full output, no transfer conversion, same output raster. Use `bilinear+accurate_rnd+full_chroma_int+bitexact` flags, one filter thread, left horizontal/center vertical 4:2:0 chroma siting (in_h_chr_pos=0, in_v_chr_pos=128 in swscale's 1/256-luma units), and explicit output format `gbrpf32le`; no intermediate PNG/RGB8 or implicit color-profile transform. The harness must verify the actual negotiated path/flags and a known legal-range YUV vector before accepting it. If the pinned build cannot honor the path, report UNSUPPORTED_REFERENCE/NOT_RUN; do not silently select a different decoder/scaler. Values below zero/above one from YUV reconstruction clip to [0,1] before inverse transfer, as this managed output profile specifies gamut clip.
3. For preview, capture the adapter's post-grade/post-output-transform sRGB pixel plane before OS display processing. The instrumented canvas/context must be explicitly sRGB with readback RGBA8/unorm8; record those properties and fail unsupported capture. Divide RGB bytes by 255 and decode sRGB. Preserve the pre-readback float tap separately for operator tests. A decorated screen capture or a browser-decoded MP4 with unverified transfer treatment is diagnostic, not this reference.
4. Decode export R'G'B' with the inverse BT.709 OETF defined below. Decode preview with inverse sRGB. This is a computational inverse OETF, not an assumption that BT.709 defines a reference-display EOTF. After the final-output compositing described in step 7 when needed, apply sRGB encoding to both linear buffers, then Q8(x)=floor(255*clamp(x,0,1)+.5), ties upward, no dither. Existing preview readback/MP4 quantization is retained as observed error; do not remove it by injecting ideal pixels into the candidate capture.
5. Native-raster comparison is mandatory, with matching geometry and no resize in the numerical reference. For a lower-resolution preview, request a separate export at the same supported raster for the primary test, retaining color-before-scale order. If that is impossible, report that case NOT_RUN and run an explicitly named resampling diagnostic: separable area integration in linear RGB over pixel cells, after transfer decoding, identical target geometry for both planes. This diagnostic cannot certify native detail or substitute for L320's existing scale=640:360 reference. No screenshot/DPR resize is hidden in a gate result.
6. Alpha preservation is tested ONLY between equivalent pre-composite operator taps: same operation/step, frame, geometry, profile, straight-alpha convention and input coverage. Compare their alpha with the existing maximum absolute error <=1/255; compare linear RGB using the existing float operator gate, canonicalizing RGB to zero where alpha is zero. An opaque MP4 is NOT an equivalent pre-composite tap, so never compare its implicit alpha=1 with a partially transparent preview alpha. Missing equivalent taps means that alpha-preservation case is NOT_RUN, not inferred from export RGB.
7. For the final encoded application gate, decode the observed preview to straight linear RGB and composite it over the declared opaque black background BEFORE the common sRGB/Q8 mapping: C_final = alpha*C_preview + (1-alpha)*(0,0,0), alpha_final=1. Compare this opaque RGB with the decoded, already opaque MP4 normalized through the same mapping; do not multiply the MP4 by preview alpha or composite the preview twice. A preview tap already composited over that black is used directly with alpha=1 and explicit post-composite tap metadata. Managed thresholds are proposed, fixed per gate version: lossless operator/tap maximum absolute linear channel error <=1e-5; encoded application swatch gate max over ROIs and RGB channels of absolute difference between ROI mean Q8 codes <=3.0. Freeze the manifest hash with the gate version before candidate measurements; never choose a new ROI after observing errors. This has its own metric ID M709-SRGB8-v1 even though the numerical bound is also 3.0; full-frame max/p95 errors and individual ROI means must also be reported as diagnostics. The transfer reference arithmetic below must match listed values within 1e-9 and integer outputs exactly.
