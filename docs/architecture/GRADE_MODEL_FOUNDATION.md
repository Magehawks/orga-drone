# Canonical grade foundation (#350)

Implementation boundary for [ADR 0035](../decisions/0035-color-workspace-contract.md), accepted by the PO in PR #367, and the [Color Workspace contract](COLOR_WORKSPACE_CONTRACT.md). This internal foundation is not an enabled workspace, migration, renderer, API or MCP feature. The full product target is retained in #350–#366; none of the remaining operators is advertised as implemented here.

## Ownership and module boundaries

Codex owns these new modules in #350:

- `src/orga_drone/studio_grade_contract.py`: typed transport-neutral GradeError, JSON/value checks, finite-data/depth/size and structural constants.
- `src/orga_drone/studio_grade_model.py`: detached opaque-preserving snapshot, version/evaluator authority, strict envelope/resource/step validation and operation descriptor discovery.
- `src/orga_drone/studio_grade_plan.py`: rational caller-supplied RenderContext, pure legacy reference evaluation and managed input/output plan metadata, content-sensitive planning digest and unresolved asset requirements.
- `src/orga_drone/studio_grade_commands.py`: bounded pure command proposals/results for later shared actions. No revision allocation, transaction, history, authorization, persistence or transport admission.

No logic is added to studio.js, app.py, db, studio_actions.py, existing render adapters or existing tests. Existing `ImageAdjust`, HSL, wheels, detail, LUT, ramp readers and `apply_keyed_image`/`apply_keyed_look` are reused; no color equations are reimplemented. Importing the existing shared action dispatcher would also import DB/catalog concerns, so this pure layer follows its transport-neutral error/validation pattern without depending on that dispatcher. #363 will map GradeError into existing transport conventions, not implement a parallel color engine.

## Read and validation contract

`read_grade(effect_settings)` accepts stored JSON text, a JSON object, or absent legacy data. A GradeModel exposes authority, evaluator, revision, schema_version, steps, selections, animation, output, diagnostics, descriptor copies and `to_dict()`; nested returned objects are detached copies. `original_effect_settings()` retains original text (including malformed legacy text) or a JSON snapshot of an object input. JSON key order/whitespace are not preserved in `to_dict()`; every opaque JSON member/value is preserved. No method writes to SQLite/disk or wraps legacy data automatically.

No `grade` means legacy-v1, version absent, revision sentinel 0; existing legacy readers retain their fallback defaults. Malformed legacy serialization is diagnostic and original text is retained. A recognizable root canonical member in damaged JSON raises INVALID_GRADE instead of silently becoming legacy. Completely ambiguous damaged text cannot establish canonical authority; callers must retain diagnostics/original input and #351 must never overwrite a failed read. `grade:null`, malformed envelope fields, duplicate JSON members in canonical input, unknown versions/evaluators, unsupported active operations, invalid references, bool-as-number, nonfinite data and oversized/deep data are explicit errors. No unknown-evaluator neutral fallback exists.

Version-1 canonical fields follow the ADR: schema_version=1, evaluator, nonnegative JS-safe integer revision, input, working, steps, selections, animation and output. Extensions are optional and opaque. The current approved structural caps are 32 steps, 32 selections, 4096 points per curve, 100000 brush points per clip and 4 MiB serialized grade bytes. Additional defensive limits are 64 JSON nesting levels, 128-character IDs and safe-integer revisions/target IDs; all failures are atomic. All resource IDs share a collision-free namespace. Selections currently have id/mask/qualifier/invert structural fields and can be retained for disabled steps, but are not executed. Canonical animation (#358) supports explicit `source-local` / `story-local` clocks on advertised scalar targets (`primaries-v1` scalars and `creative-lut-v1.strength`) with linear interpolation and `hold`/`base` outside-range policy. Unsupported targets, spatial steps, legacy-stack targets and incomplete keys raise UNSUPPORTED_GRADE / INVALID_GRADE and are never flattened. Empty animation remains supported.

Only `legacy-stack-v1` is registered now. Its parameters are the raw seven legacy sections (unknown nested members retained); missing sections materialize existing reader defaults during plan evaluation. The explicit legacy wrapper has legacy-native input/working/output, gamut=legacy, exactly one stack, mix=1 and no spatial selection when active. Wrapper construction is NOT a public migration function; tests supply synthetic wrappers to verify compatibility. The managed evaluator supports neutral/disabled-only plans with srgb, bt709-sdr or linear-bt709 input and BT.709 SDR/clip output. Non-null technical LUT metadata, active managed operators and spatial execution remain unsupported until their owned feature issues define/implement those contracts. Inactive unknown operations are preserved byte-value-for-value as JSON, even when reordered; their params are not editable through the foundation commands.

## Pure evaluation and assets

`evaluate_grade(model, context, asset_digests=...)` revalidates the model snapshot and returns RenderPlan with `to_dict()`, semantic_digest, grade_identity and assets_resolved. It evaluates no pixels. Context supplies source ID, rational source PTS, frame index, trim range, source-local time, Story time, speed, repeat pass, transition side, dimensions and orientation. Rational numerators/denominators are serialized explicitly. source_local must equal source_pts-source_in; caller timing owners provide speed-ramp/repeat mapping, not this evaluator. No clock is derived from the DOM or media files.

Legacy operations are emitted in established order: image → confirmed technical LUT → nonzero creative LUT → HSL → wheels → detail → saturation ramp, omitting neutral stages. Existing color points/ramp are evaluated at source-local time using existing helpers. Native legacy domains remain labeled legacy-ffmpeg-auto / legacy-encoded-rgb / legacy-yuv; no false claim of managed linear semantics. Active legacy animation carries a segmentation capability requirement: its historical renderer eligibility and approximation restrictions are not changed by a plan sampled at one time.

Managed neutral plans explicitly describe input transfer (inverse-srgb, inverse-bt709 or identity), linear-bt709 working domain and output transfer/range/matrix/format. `grade_identity` describes only the absence of active grade operations, not identity of input/output color conversion, geometry or compositing. Both FFmpeg/GPU capabilities are `not-integrated`, pixel_execution=false, for every plan. There is no implicit execution of these plans by the current application.

External LUT requirements include confined legacy asset ID, technical/creative role, and either caller-supplied SHA-256 or explicit unresolved state. No filesystem lookup occurs; #352 must validate actual confined bytes/domain metadata. Replacing supplied LUT content changes the semantic digest; unresolved assets cannot authorize a final render-cache hit. Generated legacy HSL/wheel artifacts remain determined by their normalized operation params; this module does not generate them. The planning digest includes evaluator/plan version, normalized ordered operations, evaluated timing, source identity, geometry, domains, capabilities and supplied asset content, and excludes grade revision, disabled operations and unrelated opaque/UI state. It is NOT a final adapter/cache key: #352/#359 add resolved asset/adapter/precision/scaler/encode identity before publication.

## Pure commands and future UI/API/MCP

`validate_patch(current, command, expected_revision)` returns GradeCommandResult with detached proposed model, positive project_id/clip_id, expected_revision, changed and persisted=false. Command shape contains exactly type/project_id/clip_id/expected_revision/params. Supported types are `set_step_enabled`, `set_step_mix` and `reorder_steps`; each strictly validates its own params. Unknown commands/fields, stale revisions, invalid IDs/permutations and enabling an unknown operation fail without mutation. Empty reorder/no-op is reported changed=false. Legacy clips cannot be implicitly wrapped. Returned revision remains unchanged: only the future transaction owner can allocate a new token atomically with history/persistence.

This prepares reusable Command/Result/Error contracts, not a new public endpoint. Target IDs are syntactically checked here; project membership, current selection, local authorization, actual current DB revision and stale UI response checks MUST be enforced by #351/#363. These pure proposals are not authorization or persistence acknowledgements. Add/update params, add/remove steps, profile/selection/preset/reset/conversion commands remain unsupported until their corresponding approved semantics and guards exist. Unknown fields are preserved on reads, not exposed as writable command params.

## P2 review correction: damaged strings before root grade

The root-key corruption guard now lexes quoted spans using quote/backslash parity instead of aborting on an invalid JSON escape. It decodes only a candidate root key; invalid unrelated strings do not prevent reaching later members. A recognizable root `grade` key establishes canonical authority even if its colon/value is missing, including the exact input `{"note":"bad\q","grade"}`. This raises INVALID_GRADE instead of producing a neutral legacy plan.

String values (including escaped quotes, Unicode text and structural punctuation), nested object/array keys and trailing documents do not establish root authority. Unterminated strings and mismatched delimiters without a previously identifiable root key remain ambiguous legacy diagnostics with original text retained. This is a conservative lexical corruption guard, not a JSON repair/migration feature; normal JSON parsing and existing legacy defaults are unchanged.

PASS on the revision: 142 foundation tests (36 added regressions), Ruff and MyPy (86 files). Regression matrix covers invalid escapes/control characters before/after the key, Unicode-escaped keys, literal escaped backslashes, missing colon/value, nested structures, embedded grade text and ambiguous/trailing inputs.
